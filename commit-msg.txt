API
- Workspace restore respects the 100-project limit (429)
- Name paging uses the database's own sort key in the cursor; search
  lowercases both sides in SQL; a bad or mismatched cursor is a 400
- SQLite: every statement goes through one queue with transactions
- Keep exactly the newest 20 revisions; restore clears dangling workspace ids
- Purge locks rows (Postgres) and relies on ON DELETE CASCADE for revisions
- Trash capped at 200 projects per owner, /trash paged
- Deployment audit is best effort; HEAD is not a share view; a broken
  Postgres client is not returned to the pool
