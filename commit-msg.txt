feat(playground,api,connect-react): conflict-safe saves, draft recovery, clearer hook errors

Playground API
- Projects get a `version` (migration 4). PUT/PATCH /projects/:id accept
  `baseVersion` and answer 409 CONFLICT with the current summary instead of
  overwriting a newer copy.
- New PATCH /projects/:id (rename, move between workspaces) and
  POST /projects/:id/duplicate (counts toward the project limit).
- CORS allows PATCH (workspace rename failed cross-origin).
- Stricter schemas for workspace names, workspaceId and GET /projects.
- Errors carry `code` and `requestId`; unknown routes return NOT_FOUND.
- README route table lists every route.

Playground
- Autosave sends the base version, runs only after real edits, and saves
  one request at a time. A conflict shows "Open the newer copy" /
  "Keep my version". Top-bar chip shows the sync state.
- ?project= stays in the URL; the draft records its version and unsaved
  edits so a reload resumes them.
- A draft replaced by a template, New, Import or Remix is stashed and can
  be restored.
- Rename and Duplicate on workspace and project cards (account and
  browser).
- Fixes: header brand follows the dApp name, Finish setup count, jumping
  to an issue from Style/Actions tabs, export panel copy.

connect-react
- connectErrorMessage(err, 'tx'): transactions no longer read
  "Connection failed"; INVALID_PARAMS shows the SDK message.
- Hooks throw BridgeError (NOT_CONNECTED / INVALID_PARAMS) when called
  too early; useQRC20, useQRC1155, useBridge, useContract return
  errorMessage; wallet error events keep INVALID_PARAMS and userHint.
- useQRC721 mint/transfer/burn accept WriteOpts.
- Polling pauses in hidden tabs and refreshes on return.
- useQRC1155().refresh deprecated (no-op). Docs list QRC-721 hooks.
